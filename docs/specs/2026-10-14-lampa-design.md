# lampa — дизайн

Дата: 2026-10-14. Статус: на ревью.

## Зачем

Игрушка-инструмент: музыка с Mac управляет умными лампами в реальном времени, а TUI — сам инструмент, на котором видно, что происходит в музыке и на каждой лампе, и где режимы, палитры и чувствительность крутятся на лету.

Замена `vibes/vibe-lights/audio_sync` + `shared/yeelight_device.py`. Оттуда ничего не переносим — переписываем, потому что:

1. Yeelight управлялся обычными командами с лимитом 60/мин (код держал 55/мин, < 1 кадра/с). Music mode (`set_music`) не использовался, а он снимает лимит.
2. Звук снимался через `soundcard` loopback, который на macOS без BlackHole не работает.
3. Алгоритмы анализа (бас по FFT, простой детектор битов) давали слабый результат.
4. W3 часто рвал соединение, восстановления не было.

## Железо и окружение

- Yeelight W3 (YLDP005), несколько WiZ-ламп, WiZ Hero (модель и возможности уточняются при обнаружении).
- macOS 27, Apple Silicon. Go 1.27, Swift 6.4.
- Сейчас лампы офлайн — всё должно работать и проверяться без них (`--dry`).

## Архитектура

                     └──────────┴──────────────▶ tui (Bubble Tea)

### tap (Swift)

Единственная задача — снять звук и отдать сэмплы.

- Core Audio Process Tap (`CATapDescription` + aggregate device), macOS ≥ 14.4.
- `lampa-tap capture [--pid N]` — без `--pid` вся система (global tap), с `--pid` — один процесс. Пишет в stdout сырые little-endian float32, моно (даунмикс), 48 kHz. Логи только в stderr.
- `lampa-tap list` — JSON-массив `{pid, name, bundleID}` процессов, которые сейчас выводят звук.
- Выход по закрытию stdout или SIGTERM, с корректным удалением tap и aggregate device.
- Первый запуск вызовет системный запрос разрешения на запись звука; это ожидаемо.

### audio (Go)

- Интерфейс `Source` выдаёт блоки `[]float32` и частоту дискретизации.
- `TapSource` запускает `lampa-tap` дочерним процессом, читает stdout, перезапускает при падении (с паузой). Смена источника (вся система ↔ приложение) = перезапуск процесса с другими аргументами.
- `WAVSource` — для тестов и `--wav file.wav` (играет в реальном темпе).

### analysis

Вход — поток сэмплов, выход — `Features` на каждый hop.

- FFT: окно Ханна 2048, hop 512 (~94 кадра/с при 48 kHz).
- 24 мел-полосы, свёртка в группы: sub (<60 Гц), bass (60–250), lowmid (250–1k), mid (1–4k), high (>4k).
- Автонормализация на полосу: пиковый «потолок» с мгновенной атакой и спадом τ ≈ 6 с, пол-шум, чтобы тишина давала ~0, а не усиленный шум.
- Onset: спектральный поток (полуволновое выпрямление разности лог-магнитуд), отдельно для low (sub+bass) и high (mid+high). Адаптивный порог = медиана за 1,5 с × k + δ; k — ручка «чувствительность».
- Темп: автокорреляция огибающей onset за ~6 с, кандидаты 70–180 BPM, взвешивание в пользу ~120. Фаза — трекинг ближайших onset с PLL-подобной коррекцией. `Confidence` ∈ [0,1]; при < 0.4 режимы работают по onset, а не по сетке долей.
- `Features`: `Time`, `Bands[24]`, `Groups{Sub,Bass,LowMid,Mid,High}`, `Loudness`, `OnsetLow`, `OnsetHigh` (bool + сила), `BPM`, `BeatPhase` ∈ [0,1), `Beat` (bool — доля прямо сейчас с учётом упреждения), `BarPhase`, `Confidence`, `Build` (нарастание энергии за последние ~8 с) .
- Компенсация задержки: доля предсказывается на `latency` вперёд (по умолчанию 60 мс, ручка ±200 мс), чтобы свет приходил вместе со звуком.

### modes

Режим — `Update(f Features, lights []LightInfo) Scene`, без побочных эффектов и сети. `Scene` — целевой цвет (OKLCH) и яркость для каждой лампы. Режимы детерминированы при одинаковом входе (кроме явного seed).

1. **Pulse** — все лампы вспыхивают на долю, цвет дрейфует по палитре, смена шага палитры на начале такта.
2. **Spectrum** — лампам назначаются группы полос (по роли из конфига или по кругу); яркость = энергия группы, оттенок — из положения группы в палитре.
3. **Chase** — на каждую долю «огонь» переходит на следующую лампу по кругу, хвост гаснет.
4. **Ambient** — медленные переходы; темп задаёт скорость дрейфа, громкость — насыщенность. Без вспышек.
5. **Drop** — при росте `Build` лампы копят яркость и насыщенность; на резком скачке low-onset после нарастания — белая вспышка всех ламп и взрыв цвета.

### color

- Интерполяция и палитры в OKLCH, конвертация в sRGB с клиппингом по хроме.
- 5–6 встроенных палитр (например: sunset, ocean, neon, forest, mono-warm).
- Сглаживание на лампу: огибающая attack/release (вспышка мгновенно, спад ~250 мс по умолчанию; Ambient — длинные).
- Гамма/кривая яркости под каждый тип лампы (у ламп нелинейная яркость и минимальный порог dimming).

### light и драйверы

```go
type Light interface {
    ID() string
    Info() LightInfo           // имя, модель, роль, макс. fps
    Apply(ctx, Frame) error    // Frame: RGB + яркость 0..1
    Snapshot(ctx) (State, error)
    Restore(ctx, State) error
}
```

- Раннер на каждую лампу — своя горутина, слот «последний кадр» (без очереди: медленная лампа берёт самый свежий кадр), ограничение fps, дедупликация одинаковых кадров, статистика (фактический fps, ошибки, статус ok/lost/reconnecting).
- **WiZ:** UDP 38899, `setPilot {r,g,b,dimming}` (dimming 10–100), до ~20 кадров/с. Без подтверждения на каждый кадр; `getPilot` раз в 1 с как heartbeat; нет ответа > 3 с → `lost`, продолжаем пинговать.
- **Yeelight:** при подключении — управляющий TCP 55443, `set_music [1, host_ip, port]`; лампа подключается к нашему TCP-листенеру, дальше `set_rgb`/`set_bright` с `"sudden"` в это соединение, до ~20 кадров/с. Обрыв → переподключение с экспоненциальной паузой (0.5 → 8 с). Если в `support` из обнаружения нет `set_music` — fallback: 1 кадр/с, `"smooth"` переходы, предупреждение в TUI.
- Snapshot состояния до старта; на выходе (q, Ctrl-C, SIGTERM) — Restore всех ламп, у Yeelight — `set_music [0]`.

### discovery

- WiZ: UDP broadcast `getSystemConfig` на 38899, ответы в течение ~2 с → MAC, IP, moduleName.
- Yeelight: SSDP `M-SEARCH` на 239.255.255.250:1982 → id, location, model, support.
- Результат можно сохранить в конфиг из TUI.

### config

`~/.config/lampa/config.toml`: список ламп (тип, IP, id/MAC, имя, роль, enabled), последний режим, палитра, чувствительность, задержка, источник звука. Отсутствие файла — не ошибка (запускается с обнаружением).

### tui

Bubble Tea + Lipgloss. ~30 fps отрисовки, независимо от анализа.

- Шапка: режим, BPM + индикатор доли, источник звука.
- Спектр 24 полосы, лента onset/долей за последние ~2 с.
- Плашки ламп в реальном отправленном цвете + фактический fps + статус.
- Клавиши: `1–5` режим, `p` палитра, `←/→` чувствительность, `↑/↓` задержка, `s` выбор источника (вся система / список приложений из `lampa-tap list`), `d` поиск ламп, `space` пауза (лампы держат последний кадр), `q` выход с восстановлением.

### CLI

`lampa [--dry] [--wav file] [--config path]`. `--dry` — без ламп (виртуальные лампы только в TUI). `lampa discover` — разовый поиск и печать.

## Ошибки

- Падение tap → перезапуск, в TUI «нет звука»; анализ получает тишину, лампы плавно гаснут к фону.
- Отказ разрешения на запись звука → понятное сообщение, как включить в System Settings.
- Ни одна лампа не отвечает → работа продолжается, статусы `lost`.
- Ошибка одной лампы никогда не останавливает другие и не роняет TUI.

## Тесты

- `analysis`: синтетика — метроном 120 BPM (BPM ±2, доли в пределах ±20 мс после прогрева), синус 80 Гц (энергия в bass, не в high), тишина (Loudness ≈ 0, нет onset), щелчки в верхах (OnsetHigh без OnsetLow). Пара коротких реальных WAV в `testdata/` как smoke.
- `modes`, `color`: таблицы Features → Scene, свойства (Chase — ровно одна яркая лампа на долю; Ambient — нет скачков больше порога между кадрами).
- Драйверы: фейковый WiZ (UDP) и фейковый Yeelight (управляющий TCP + обратное подключение music mode, обрыв посреди потока → переподключение).
- Раннер: медленная лампа не блокирует быструю; дедупликация.
- `tap`: ручная проверка (играет музыка → ненулевые сэмплы; `--pid` Spotify → только Spotify).
- `go test ./... -race` должен проходить.

## Вне скоупа v1
